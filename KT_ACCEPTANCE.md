## Повторяемый стенд

`scripts/prepare-acceptance.ps1` проверяет SHA-512 закреплённых пяти файлов и готовит build/kt-*.
Затем `gradlew runServer -PtcAcceptance`, `gradlew runClient -PtcAcceptance` и
`gradlew prepareClient2Run -PtcAcceptance`; второй клиент можно запустить `scripts/run-kt-client2.ps1`.
Его javaw использует classpath работающего первого клиента. Это средство воспроизведения, не исправление GLFW.
Не запускать два экземпляра клиента в одной папке.

При `-PtcAcceptance` подключаются только классы из tools/kt/java. Сервер читает команды оператора из
build/kt-server/commands.txt раз в 10 тиков, работает лишь с маркером tc-acceptance. Готовый файл команд
следует переносить на это имя атомарно, не дописывать во время чтения. KtOne/KtTwo получают права оператора
и творческий режим. Наблюдатель клиента только пишет attachments/слоты/экран и различает заголовки окон;
нажатия и мышь выполняются Windows-инструментом. Не использовать этот режим на публичном сервере.
Обычный build не включает эти служебные классы; итоговый jar проверен отдельно.

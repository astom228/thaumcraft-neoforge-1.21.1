# План порта Thaumcraft 6 (1.12.2) → NeoForge 1.21.1

Основано на декомпиляции `Thaumcraft-1.12.2-6.1.BETA17.jar` (Vineflower 1.12.0) в `reference/src/thaumcraft`.

## 0. Общая картина оригинала

| Что | Объём |
|---|---|
| Java-классов | ~910 (из них ~100 — API `thaumcraft.api`, ~45 — встроенная `codechicken.lib`) |
| Блоков | ~120 регистраций (`ConfigBlocks`, 526 строк) |
| TileEntity | 47 |
| Предметов | ~105 регистраций (`ConfigItems`), многие с вариантами по metadata |
| Сущностей | ~43 (`ConfigEntities`) |
| Эффектов (Potion) | 9 |
| Биомов | 3 (Magical Forest, Eerie, Outer Lands) |
| Пакетов сети | ~35 (`common/lib/network`) |
| GUI / Container | 18 экранов, 21 контейнер |
| Рецепты | **только в коде** (`ConfigRecipes`, ~3000 строк), JSON-рецептов нет |
| Исследования | JSON в `assets/thaumcraft/research/*.json` (9 файлов) |
| Ассеты | 840 текстур, 111 звуков, 217 blockstates (169 в формате `forge_marker`), 27 OBJ-моделей, 3 шейдера, 8 языков (`.lang`) |
| Рендер | GL11 / `GlStateManager` в ~137 файлах, `Tessellator` в ~41, ARB-шейдеры, свой OBJ-загрузчик |

Точка входа: `thaumcraft/Thaumcraft.java` → `proxies/CommonProxy` (preInit/init/postInit) + `Registrar` (события регистрации).

## 1. Системы мода

1. **Ядро / регистрации** — `Registrar`, `ConfigBlocks`, `ConfigItems`, `ConfigEntities`, `ModConfig`, `SoundsTC`, `CreativeTabThaumcraft`, `CommandThaumcraft`, IMC.
2. **Базовые блоки и предметы** — камни, металлы, руды (amber, cinnabar, quartz), дерево (greatwood, silverwood), листья, саженцы, ступени, плиты, янтарь, растения (shimmerleaf, cinderpearl, vishroom), ресурсы (слитки, самородки, кластеры, пластины, ткань, механизмы, салис мундус и т.д.).
3. **Аспекты** — `api/aspects` (`Aspect`, `AspectList`, `AspectHelper`), `ConfigAspects` (900 строк привязок аспектов к предметам/сущностям, через OreDictionary), генерация аспектов из рецептов (`ThaumcraftCraftingManager`), кристаллы эссенции, подсказки с аспектами.
4. **Исследования и Таумономикон** — `ResearchManager`, `api/research` (категории, записи, стадии, аддендумы, сканирование), JSON-исследования, теорикрафт (`research/theorycraft`, 37 карт/помощников), стол исследований, таумометр, знания (`PlayerKnowledge`), `GuiResearchBrowser` (1373 стр.), `GuiResearchPage` (2371 стр.), `ResearchToast`.
5. **Тигель и алхимия** — `TileCrucible`, `CrucibleRecipe`, салис мундус и «пыльные триггеры» (`DustTrigger*` — превращение блоков/мультиблоков).
6. **Магический верстак** — `TileArcaneWorkbench`, `ShapedArcaneRecipe`/`ShapelessArcaneRecipe`, расход vis из ауры, зарядник верстака.
7. **Инфузия** — `TileInfusionMatrix`, пьедесталы, стабилизаторы, нестабильность, `InfusionRecipe`, `InfusionEnchantmentRecipe`, `InfusionRunicAugmentRecipe`, инфузионные зачарования (`EnumInfusionEnchantment`).
8. **Эссенция и трубы** — банки (обычная/void/brain), 6 видов труб, центрифуга, плавильня (3 вида + вентиль/aux), алембик, термос/буфер, зеркала эссенции, тауматориум, ввод/вывод эссенции, ярлыки, фиалы, `EssentiaHandler` (удалённый забор эссенции).
9. **Аура и флюкс** — `world/aura` (`AuraChunk`, `AuraWorld`, `AuraHandler`, `AuraThread` — отдельный поток), сохранение в `ChunkEvents`, загрязнение, флюкс-разлом (`EntityFluxRift`), флюкс-слизь, vis-генератор/батарея, конденсатор, стабилизатор, HUD ауры.
10. **Кастер и фокусы** — `api/casters` (`FocusEngine`, узлы: medium/effect/mod), 20 классов фокусов, `ItemCaster`, фокусный манипулятор (GUI-редактор узлов), мешочек фокусов, клавиши (`KeyHandler`), радиальное меню (`WandRenderingHandler`).
11. **Инструменты, броня, безделушки** — thaumium/void/elemental инструменты, primal crusher, crimson blade, grapple gun, броня (thaumium, cloth/robe, fortress, void, cultist, praetor), очки откровения, ботинки странника, безделушки через **Baubles** (AMULET, RING, BELT, HEAD, CHARM), runic shielding.
12. **Устройства** — лампы (3), arcane ear, левитатор, мехи, адская печь, spa, распылитель зелий, hungry chest, redstone relay, recharge pedestal, диоптра, баннеры, portable hole, arcane bore, турели, рельсы, paving stones, pattern crafter.
13. **Варп** — `PlayerWarp`, `WarpEvents` (380 стр.), эффекты, sanity checker/soap, «шёпоты».
14. **Порча (taint)** — блоки taint (soil, rock, crust, geyser, log, fibre, feature), распространение, семена порчи, флюкс → порча, бутылка порчи.
15. **Существа** — ~43 сущности: pech, wisp, brainy zombie, fire bat, eldritch crab/guardian/warden/golem, cultists (knight/cleric/leader, порталы), taint-мобы, thaumic slime, mind spider, турели, снаряды, «чемпионы» (17 модификаторов `monster/mods`), боссы.
16. **Големы** — `EntityThaumcraftGolem`, детали (материал/голова/руки/ноги/аддон), 15 AI-задач, печати (`seals`, 19 классов), задачи, логистика (`GuiLogistics`), сборщик големов, колокольчик, OBJ-модели.
17. **Генерация мира** — `ThaumcraftWorldGenerator` (руды, растительность, «узлы»/кристаллы, нижний мир), деревья greatwood/silverwood, курганы (`WorldGenMound`), 3 биома (в обычном мире генерируется только Magical Forest), лут.
18. **Рендер и частицы** — `FXDispatcher` (1416 стр.), 19 частиц, лучи/дуги, TESR (21), рендереры сущностей (40+), модели (`ModelBase`), свой OBJ-загрузчик, встроенная codechicken lib, ARB-шейдеры (ender, флюкс-разлом, portable hole), HUD (`HudHandler`), `RenderEventHandler` (868 стр.).
19. **GUI** — 18 экранов, 21 контейнер, 14 слотов, `ProxyGUI`/`IGuiHandler`.
20. **Сеть** — `PacketHandler` (SimpleNetworkWrapper), ~35 пакетов (fx, misc, playerdata).

## 2. Зависимости между системами

```
Ядро/регистрации ─┬─> Базовые блоки/предметы ─┬─> Аспекты ─┬─> Тигель/алхимия ─┐
                  │                           │            ├─> Эссенция/трубы ─┼─> Инфузия ─> Инструменты/броня (инфузионные)
Сеть ─────────────┤                           │            └─> Исследования ───┘
Данные игрока ────┤                           │
(знания, варп)    │                           └─> Генерация мира (руды, деревья, растения)
                  │
Аура/флюкс ───────┼─> Магический верстак (vis) ─> Кастер/фокусы
                  └─> Порча ─> taint-мобы
Рендер/частицы ── нужен почти всем (вводится рано, расширяется по ходу)
GUI/контейнеры ── верстак, стол исследований, плавильня, манипулятор, големы...
Существа ── зависят от рендера моделей; големы ── от существ, печатей, эссенции/логистики
Варп ── от данных игрока и исследований
```

Ключевые связи:
- **Аспекты** — фундамент: от них зависят сканирование, исследования, тигель, эссенция, инфузия, кристаллы.
- **Исследования** гейтят почти все рецепты (каждый рецепт привязан к ключу исследования).
- **Аура** нужна верстаку, кастеру, генераторам vis, флюксу и порче.
- **Эссенция** нужна инфузии (забор из банок) и големам (логистика).

## 3. Сквозные проблемы перехода 1.12.2 → 1.21.1

Касаются всех этапов, решаются один раз в начале:

1. **SRG-имена в декомпиляции.** Код содержит `func_177958_n` вместо `getX`. Для чтения стоит прогнать `reference/src` через маппинги MCP `stable_39` (1.12) — простая замена по `fields.csv`/`methods.csv` (в отдельную копию, оригинал не трогать).
2. **«Уплощение» (Flattening, 1.13).** Нет metadata у блоков и предметов. `ingot` с вариантами `thaumium/void/brass` → отдельные предметы. Имена брать из названий вариантов оригинала (`ItemTCBase.VARIANTS`, имена моделей), чтобы текстуры/переводы совпали. Блоки с `PropertyEnum` → отдельные блоки или BlockState-свойства.
3. **NBT у ItemStack → Data Components (1.20.5).** Аспекты в кристаллах/фиалах, данные кастера и фокусов, ярлыки, инфузионные зачарования, броня — всё через зарегистрированные `DataComponentType` с кодеками.
4. **OreDictionary → теги.** `ConfigAspects` и рецепты используют `"ingotIron"`, `"dyeBlack"` и т.п. → `c:ingots/iron`, `c:dyes/black`.
5. **Рецепты в коде → JSON-рецепты из datapack.** Писать datagen (`RecipeProvider`), повторяющий `ConfigRecipes` 1:1. Свои типы рецептов (arcane, crucible, infusion) — `RecipeType` + `RecipeSerializer` + `MapCodec`/`StreamCodec`. Рецепты теперь только на сервере → всё, что клиент брал из рецептов (Таумономикон, генерация аспектов), надо синхронизировать.
6. **Регистрация.** `GameRegistry`/`Register<T>` → `DeferredRegister`; `Potion` → `MobEffect` (Holder); `SoundEvent`, `BlockEntityType`, `MenuType`, `EntityType`, `DataComponentType`, `ParticleType`, `CreativeModeTab` — свои регистры.
7. **Capabilities игрока (`PlayerKnowledge`, `PlayerWarp`) → Data Attachments** с сериализацией и копированием при смерти.
8. **Сеть.** `SimpleNetworkWrapper`/`IMessage` → `CustomPacketPayload` + `StreamCodec`, регистрация через `RegisterPayloadHandlersEvent`.
9. **Рендер.** Immediate mode GL11/`Tessellator` убран. Всё переписывается на `PoseStack` + `VertexConsumer`/`MultiBufferSource` + `RenderType`. ARB-шейдеры → core-шейдеры (`RegisterShadersEvent`). `ModelBase` → `EntityModel` + `LayerDefinition`. TESR → `BlockEntityRenderer`. Это самая трудоёмкая часть порта.
10. **Ассеты** (содержимое не меняется, меняется только формат):
    - `.lang` → `.json` (конвертация ключ=значение 1:1, кроме ключей, которые изменились из-за уплощения);
    - 169 blockstates `forge_marker` → ванильный формат;
    - текстуры лежат в `textures/blocks`/`textures/items`, а атлас 1.21 по умолчанию берёт `block/`/`item/` → добавить источник атласа (`atlases/blocks.json`), не переименовывая файлы;
    - 2 файла с заглавными буквами (`particleMote.png`, `Thaumaturge_eyes.png`) — в 1.21 ResourceLocation только в нижнем регистре: придётся переименовать (единственное вынужденное изменение имени, содержимое то же);
    - формат loot tables и моделей предметов с OBJ изменился.
11. **Baubles отсутствует на 1.21.1.** Замена — Curios API (слоты necklace/ring/belt/head/charm). Это вынужденное отступление от 1:1 — согласовать перед этапом.
12. **Конфиг.** `@Config` → `ModConfigSpec`.
13. **Измерения.** `int dim` → `ResourceKey<Level>`.

## 4. Этапы (от простого к сложному)

После каждого этапа: `gradlew build`, запуск клиента, коммит.

### Этап 1. Каркас
Главный класс, `DeferredRegister`-ы, вкладка творческого режима, конфиг, звуки (`sounds.json` + 111 ogg), перевод `.lang` → `.json`, атлас для `textures/blocks|items`, логгер.
**Сложно:** конвертация lang и решение по ключам перевода для уплощённых предметов; `@Mod`-аннотация и события вместо прокси.

### Этап 2. Простые блоки и предметы
Камни, металлические блоки, руды, янтарь, дерево/листья/саженцы/доски/ступени/плиты, ресурсы (слитки, самородки, кластеры, пластины, ткань, механизмы, ворс и т.д.), ванильные рецепты (datagen), плавка, loot tables блоков, теги.
**Сложно:** уплощение вариантов; конвертация `forge_marker` blockstates; листья/саженцы (новые API деревьев — `TreeGrower`); ступени/плиты с другими конструкторами; теги вместо OreDictionary.

### Этап 3. Сеть и данные игрока
Регистрация payload-ов, Data Attachments для знаний и варпа, синхронизация при входе/респауне/смене измерения, команда `/thaumcraft` (Brigadier).
**Сложно:** перенос ~35 пакетов на `StreamCodec`; копирование данных при смерти; Brigadier вместо `CommandBase`.

### Этап 4. Аспекты
`Aspect`, `AspectList` (+ кодеки), реестр аспектов предметов/сущностей (`ConfigAspects` 1:1, через теги), генерация аспектов из рецептов, кристаллы эссенции, отображение аспектов в подсказке, иконки аспектов.
**Сложно:** `ThaumcraftCraftingManager.generateTags` обходит все рецепты — в 1.21 рецепты доступны только на сервере после загрузки datapack, нужен пересчёт при `/reload` и синхронизация на клиент; NBT кристалла → Data Component; сущности по строковым именам → `EntityType`.

### Этап 5. Аура и флюкс (основа)
Данные ауры по чанкам (vis/flux/base), сохранение, расчёт, синхронизация, HUD, загрязнение, флюкс-слизь, vis-кристаллы.
**Сложно:** `AuraThread` работает в отдельном потоке и трогает мир — в 1.21 это небезопасно; нужно сохранить тот же алгоритм и частоту (раз в секунду), но выполнять на серверном тике или аккуратно изолировать данные. Хранение в чанке: `ChunkDataEvent` → chunk Data Attachment.

### Этап 6. Инфраструктура рендера и частиц
Базовые частицы из `FXDispatcher`, `ParticleRenderType`, лучи/дуги/искры, порт нужных частей встроенной codechicken lib и OBJ-загрузчика Thaumcraft на `VertexConsumer`, первые `BlockEntityRenderer`.
**Сложно:** весь immediate-mode GL; блендинг/глубина через `RenderType`; шейдеры ARB → core shaders; частицы, которые рисуют в мировых координатах вручную.

### Этап 7. Исследования и Таумономикон
Загрузка JSON-исследований, категории, стадии, требования, сканирование (таумометр, `ScanningManager`), знания/наблюдения, стол исследований и теорикрафт (карточки), `GuiResearchBrowser`, `GuiResearchPage`, тосты, книга, свиток/записи.
**Сложно:** ~3700 строк GUI на GL11 → `GuiGraphics`; строковые ссылки на предметы с metadata/NBT в JSON (`thaumcraft:crystal_essence;1;0;{Aspects:[...]}`) → парсер с переводом в уплощённые ID и компоненты; страницы рецептов требуют рецепты с сервера; меню стола (Container → `AbstractContainerMenu` + `MenuType`).

### Этап 8. Магический верстак
Верстак, `ShapedArcaneRecipe`/`ShapelessArcaneRecipe` (тип + сериализатор), расход vis, кристаллы в слотах, зарядник, салис мундус и превращения (`DustTrigger*`).
**Сложно:** собственный `RecipeType` с `CraftingInput`; синхронизация результата в меню; мультиблок-триггеры.

### Этап 9. Тигель и алхимия
Тигель (жидкость, кипение, растворение предметов в аспекты, выбросы флюкса), `CrucibleRecipe`, рендер содержимого.
**Сложно:** жидкости — `FluidStack`/`IFluidHandler` поменялись; рендер поверхности тигля на `VertexConsumer`; столкновения предметов с блоком (`entityInside`).

### Этап 10. Эссенция и трубы
Банки, трубы (6 видов), центрифуга, плавильни, алембики, буфер, фильтры, ярлыки, фиалы, зеркала эссенции, тауматориум, ввод/вывод эссенции.
**Сложно:** сетевая логика `IEssentiaTransport` (всасывание/давление) — перенести 1:1; модели труб с соединениями (многочастные blockstates); TESR банок и эссенции; синхронизация BlockEntity (`getUpdatePacket`/`getUpdateTag` изменились).

### Этап 11. Инфузия
Матрица, пьедесталы, стабилизаторы, нестабильность и её события, `InfusionRecipe`, инфузионные зачарования и рунические улучшения, `EssentiaHandler`, мультиблок через салис мундус.
**Сложно:** рецепты инфузии с NBT-компонентами; инфузионные зачарования как Data Component и их эффекты в событиях инструментов (`ToolEvents`); зачарования в 1.21 data-driven (если где-то используются ванильные).

### Этап 12. Кастер и фокусы
Кастер, `FocusEngine` и узлы, 20 фокусов, фокусный манипулятор (GUI-редактор), мешочек, клавиши, радиальное меню, снаряды фокусов.
**Сложно:** дерево узлов фокуса в NBT → компоненты; рендер радиального меню; `KeyMapping` регистрация; снаряды → новые `Projectile`.

### Этап 13. Инструменты, броня, безделушки
Все инструменты и броня, модели брони (`ModelCustomArmor` и др.), очки откровения (HUD аспектов/ауры), ботинки странника, runic shielding, безделушки через Curios.
**Сложно:** `ArmorMaterial` в 1.21 — регистр Holder-ов; кастомные модели брони через `IClientItemExtensions`; `Tier`/инструменты на data components; Baubles → Curios (см. сквозную проблему 11).

### Этап 14. Устройства
Лампы, arcane ear, левитатор, мехи, адская печь, spa, распылитель, hungry chest, relay, recharge pedestal, диоптра, баннеры, portable hole, vis-генератор/батарея, конденсатор, стабилизатор, paving stones, pattern crafter.
**Сложно:** редстоун-API, ticker-ы BlockEntity (`BlockEntityTicker` вместо `ITickable`), portable hole (временная замена блоков + шейдер).

### Этап 15. Варп и порча
Варп и его события, эффекты (9 `MobEffect`), блоки порчи и распространение, семена порчи, флюкс → порча, предметы-лекарства.
**Сложно:** распространение порчи через случайные тики и замену биома; эффекты с кастомным рендером (размытое зрение, виньетка) на новом HUD-слое.

### Этап 16. Существа
Все мобы, снаряды, «чемпионы», боссы (с полосами здоровья), культисты и порталы, pech-торговля, спавны.
**Сложно:** ~40 моделей `ModelBase` → `LayerDefinition` (механически, но много); AI `EntityAI*` → `Goal`; атрибуты сущностей через событие; спавны → biome modifiers (JSON); `DataParameter` → `EntityDataAccessor`; pech GUI.

### Этап 17. Генерация мира
Руды, растения, деревья greatwood/silverwood, курганы, vis-кристаллы, лут-сундуки/урны, биом Magical Forest в обычном мире (TerraBlender); Eerie и Outer Lands — только регистрация (в оригинале не генерируются, см. DECISIONS.md п. 11).
**Сложно:** генерация в 1.21 data-driven (`ConfiguredFeature`/`PlacedFeature` + biome modifiers); собственные генераторы деревьев → `Feature`; биомы — JSON, Magical Forest вставляется регионом TerraBlender (веса WARM/COOL из оригинала напрямую не переносятся — подобрать максимально близко); добавление в ванильный лут → Global Loot Modifiers.

### Этап 18. Големы
Голем-сущность, детали, OBJ-модели, сборщик големов, печати и их зоны/рендер, задачи, логистика, колокольчик, турели.

## 5. Локализация (мод полностью на русском)

### Что есть в оригинале
- Языки: `assets/thaumcraft/lang/*.lang` (en_us, ru_ru, de_de, ja_jp, ko_kr, nl_NL, zh_cn, zh_tw), UTF-8, формат `ключ=значение`.
- `ru_ru.lang` **есть, но сильно неполный.** По заголовку файла это перевод для 6.1.**BETA13** (авторы: TimeConqueror, groting, Daddy Lappy, DCV_Hacker), а мод — BETA17.
  - Ключей: en_us — 1435, ru_ru — 1439.
  - Реально переведено (есть кириллица) — **~365 строк**; ~1080 строк присутствуют, но значение осталось английским (скопировано из en_us).
  - 38 ключей en_us отсутствуют в ru_ru вовсе: новое в BETA14–17 (`FLUXCLEANUP`, `FLUXRIFT`, `INFUSIONSTABLE`, `RIFTCLOSER`, `SEALSTOCK`, `VISBATTERY`, `VISGENERATOR`, `stability.*`, `tc.condenser*`, конденсатор, стабилизатор, vis-генератор/батарея и др.).
  - 42 ключа есть только в ru_ru — устаревшие (`entity.TravelingTrunk`, `tc.key1..11`, `tc.wandcharge` и т.п.); в игре не используются, переносить не нужно.
  - Не переведены, в частности: почти все предметы и блоки (`item.*` — 179, `tile.*` — 146), големы/печати (`golem.*` — 113), фокусы, кнопки GUI, сущности, эффекты.
- **Тексты Таумономикона хранятся в тех же lang-файлах**, а не в отдельных файлах:
  - `assets/thaumcraft/research/*.json` содержат только структуру и ключи (`"name": "research.X.title"`, `"text": "research.X.stage.N"`);
  - сами тексты лежат в `.lang`: `research.<KEY>.title` (132), `research.<KEY>.stage.N` (263), `research.<key>.text` (27, сканирование/наблюдения), а аддендумы ссылаются на произвольные ключи (`research.ESSENTIASMELTER.bellows`, `research.ORE.amber` и т.п.);
  - `GuiResearchPage` получает их через `I18n` и разбирает разметку `<IMG>`, `<BR>`, `<LINE>`, `<PAGE>`, `<DIV>`;
  - в en_us 438 ключей `research.*` (~135 тыс. символов) — это основной объём перевода; в ru_ru переведено только **54** из них.
- Захардкоженного английского в интерфейсе (в Java-коде) нет — только сообщения логов/ошибок.

### Как переносим
1. Конвертер `.lang` → `.json` для `en_us` и `ru_ru` (только смена формата; значения 1:1, переводы строк и разметка сохраняются).
2. Ключи переименовываются там, где 1.21 требует другой формат: `item.X.name` → `item.thaumcraft.X`, `tile.X.name` → `block.thaumcraft.X`, `entity.X.name` → `entity.thaumcraft.X`, `potion.*` → `effect.thaumcraft.*`, `enchantment.*`, уплощённые варианты (`item.ingot.thaumium.name` → `item.thaumcraft.ingot_thaumium` и т.п.). Значения не меняются.
3. Для ru_ru: взять перевод из оригинала; где строки нет или она английская — перевести на русский в терминологии уже переведённых строк оригинала.
4. Новые строки 1.21 (биомы `biome.thaumcraft.*` — в оригинале имена биомов захардкожены, вкладка творческого режима, категории и названия клавиш, конфиг, субтитры звуков, тексты Curios-слотов и т.п.) — сразу в оба файла.
5. Перевод делать по этапам: на каждом этапе переводятся строки тех блоков/предметов/исследований, которые в нём переносятся. Тексты исследований — вместе с этапом 7 и далее по разделам (Основы, Алхимия, Артифайс, Инфузия, Големантия, Ауромантия, Элдрич).

# Изолированная игровая приёмка

Классы `java/` подключаются только с `-PtcAcceptance`. Файлы `GlfwFocusProbe.java` и `FocusBridge.cs`
вне этого source root и компилируются отдельно, в `build/glfw-probe`; в мод они не попадают.
Запуски и результаты — `KT_ACCEPTANCE.md`, нативный сбой и обход — `GLFW_FOCUS_AUDIT.md`.

Сервер: `scripts/prepare-acceptance.ps1`, затем `gradlew runServer -PtcAcceptance`.
Клиент 1: `gradlew runClient -PtcAcceptance`; клиент 2: `gradlew prepareClient2Run -PtcAcceptance`,
затем `scripts/run-kt-client2.ps1` (первый клиент уже запущен).
Для точного применения в мире в тестовых options.txt стоят `key_key.use:key.keyboard.v`
и `key_key.attack:key.keyboard.j`; в GUI — обычная мышь. Перед уходом из мира в другое окно
полезно открыть Escape, чтобы отпустить захват мыши. Переход между Minecraft всегда через FocusBridge.
Второй Minecraft запускается видимым (`WindowStyle Normal`), поскольку пользователь прямо запросил
интерактивную игровую проверку. Скрытое окно затрудняло захват и активацию.

Нейтральное окно имеет отдельный exe, чтобы не объединяться Windows-инструментом с java/javaw:
`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /reference:System.Windows.Forms.dll /reference:System.Drawing.dll /out:C:\mods\thaumcraft-port\build\glfw-probe\KtFocusBridge.exe C:\mods\thaumcraft-port\tools\kt\FocusBridge.cs`.
После компиляции открыть это собственное приложение штатным computer-use, затем работать по двум шагам:
активировать нейтральное окно и проверить его скриншот; активировать нужный Minecraft и проверить его скриншот.
Перед вводом сверять заголовок на изображении с нужным игроком: захват фонового OpenGL-окна иногда показывал другое.

После каждого UI-действия клиент сохраняет наблюдаемое состояние в `build/kt-client*/state.json`
раз в секунду: экран, слоты и полные компоненты, предмет на курсоре, знания/Искажение, направление,
Вис открытого верстака и последние звуки, которым реально выделен источник воспроизведения.
Физическое прослушивание звука эта запись не доказывает.

Команды сервера публикуются атомарной заменой `build/kt-server/commands.txt` из готового временного файла.
Обычные строки — команды консоли Minecraft. Дополнительные команды только этого стенда:

- `kt:watch x y z` — добавить загруженный блок в наблюдение, без загрузки его чанка.
- `kt:aura chunkX chunkZ vis` — фиксировать Вис существующего чанка для проверки нехватки/оплаты.
- `kt:aura-clear` — снять фиксацию. Она не восстанавливает прежний Вис; управляемую цену нужно вернуть явно.

Сервер пишет `server-state.json` со слотами/знаниями/Искажением игроков и полным NBT наблюдаемых блоков.
Это наблюдение и подготовка исходного состояния; клики, изготовление, применение предметов и
проверка изображения выполняются настоящими клиентами. Управление UI через эти классы не выполняется.

Не запускать режим приёмки на публичном сервере: он выдаёт оператора тестовым KtOne/KtTwo.
После завершения — корректный `stop`, закрытие клиентов, обычный `gradlew build`, проверка jar
на отсутствие DebugAcceptance/DebugAcceptanceClient. Миры и сырые доказательства хранятся только в build.
